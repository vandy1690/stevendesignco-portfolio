	<div><dt>Where</dt><dd>The foot of every case study page and the design

## In code

`src/components/ui/Pager.astro`, and `PagerPair.astro` which owns the whole
closing band so a page cannot put it in the wrong place.

```astro
---
import PagerPair from '../../components/ui/PagerPair.astro';
---
<PagerPair
	prev={{ href: '/work/plate', label: 'Plate', hidden: 'Previous case study: ' }}
	next={{ href: '/work/alt-meat', label: 'Alt-Meat', hidden: 'Next case study: ' }}
/>
```

Each link takes `href`, `label` and `hidden`. `label` is the visible text and
stays the visible text. `hidden` is read before it, which is how the direction
reaches a screen reader without an `aria-label` replacing what is on screen.

`Pager` on its own takes `dir` of `prev` or `next`, which picks the chevron and
the side it sits on. Use `PagerPair` unless you have a reason not to.

## Anatomy

The visible text is the destination name only: "Plate", not "Next: Plate". The
arrow carries the direction, so repeating it in words is noise for people who
can see it.

For people who cannot, the direction is supplied as screen-reader-only text
inside the link: hidden text reading "Next case study: " sits before the
destination, so the link announces as "Next case study: Plate" while showing
"Plate".

That distinction matters and was got wrong once. The direction was originally an
`aria-label` on the link, which replaces the visible text rather than adding to
it. An audit flagged it, correctly: a person using voice control who says
"click Plate" must be able to activate what they can read. Hidden text extends
the name; a label replaces it. Only one of those is safe.

## States

Rest is charcoal with paper-coloured text. Hover inverts to the slate accent
with white text. The end cap is a translucent panel over the button fill, so it
shifts with the button rather than being its own colour.

In Windows High Contrast Mode the fill and cap are forced to system colours and
the cap becomes a border, since a background-painted divider disappears there.

## Responsive behaviour

On phones the pair stays on one row. Each pager takes half the width, grows
taller as needed, and wraps its own label across two lines rather than dropping
the pair into a stack. Minimum height on phones is 44px.

## Content

The destination name, exactly as that case study is titled elsewhere. Shorten a
long title rather than letting it wrap three times: "Becoming the Default at
Checkout" is "Default at checkout" on the pager.

The last case study in the chain points back to the index instead, labelled
"Back to all work".

		</ul>
	</div>

## Checks before you ship

1. The visible text is a destination name with no "Next" or "Previous" in it.
2. A screen reader announces the direction before the name.
3. At 390px wide, both pagers sit on one row and no label is cut off.
4. The pair reads previous on the left, next on the right.
