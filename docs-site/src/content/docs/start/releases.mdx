The current version is **SDC {sdc.version}**. The number lives in one file,
`src/styles/tokens/sdc-version.json`, and the site, the Storybook and these docs
all read it from there. The live site carries it too, in
`<meta name="sdc-version">`, so one request tells you which version is in
production.

## How the number works

Semantic versioning, the common practice: **major.minor.patch**, written with
two digits each, for example `02.00.00`.

| Part | Goes up when | Example |
| :-- | :-- | :-- |
| Major | Something that used the system before would break: a token, class or component name changes or goes away, or a component's markup contract changes. | Namespacing every token and class with `sdc-`. |
| Minor | Something is added without breaking what exists: a new token, component, pattern or variant, or a visual change that keeps every name. | Button padding moving onto the spacing scale. |
| Patch | A fix or a refactor that changes no name and no intended look: documentation, a bug fix that restores the intended rendering. | A docs page correcting a class name. |

The test is the consumer's code, not the visitor's eye. A rename is invisible
on the page and still a major version, because every selector and every
`var()` written against the old name stops working.

Each release gets a git tag, `sdc-` plus the number, on the commit that reached
production.

## Log

### 02.02.01 · October 27, 2026

Patch: nothing added and nothing renamed. The system did not change; what the
system says about itself did.

- **`custom-elements.json` now covers the whole library.** It described eight
  custom elements and the library has twenty-three components, and
  `manifest:check` passed anyway, because it verified the eight it knew about
  rather than whether anything was missing. The components that keep their
  native element now appear as plain class declarations, with their props as
  members and the classes they write under `sdcClasses`. A consumer that wants
  only custom elements filters on `customElement` and gets exactly the same
  eight back.
- **[Every component](/docs/components/)**, a new page: the whole library in one
  table, with each component's summary, what it renders, its props and a link to
  its page, and a second table of the patterns that are CSS and markup only. Both
  are generated, the first from `src/components/ui/` and the second from the
  pages no component claims, so the two halves cannot disagree about which is
  which.
- **Every component declares where it is documented**, with `@docs` in its doc
  comment. `manifest:check` now fails if a component has no pointer, if the
  pointer names a page that does not exist, or if a component is missing from
  the manifest. Adding a component to the folder can no longer leave it
  invisible.
- Four documents that had gone out of step with the code are corrected:
  `ARCHITECTURE.md` had a component count and a duplicate list of the library,
  both of which now point at the generated one; `DESIGN-SYSTEM.md` gains the
  control classes and the two control tokens that shipped in 02.02.00;
  `start/naming` described the manifest as the attribute API of every element,
  which read as the component API and was a third of it; `start/how-to-read`
  listed fourteen components by name when there were twenty-three.
- `llms.txt` says the design system exists. It is one of the surfaces an agent
  reads first and it had no line for the documentation, the manifest or the
  Storybook.

**And the documentation site's own accessibility**, tested for the first time.
The Q&A suite covers the eleven site routes; these 47 pages had never been run
through it. Two defects across every component page:

- `docs-site/src/styles/sdc.css` is a hand-written copy of the handful of tokens
  Starlight needs, and it carried the ink values once, in `:root`, with no value
  for the dark theme it ships a toggle for. The muted ink was also the value the
  site **retired on 5 October** for failing on its deepest light ground. It
  measured **2.80 in dark and 4.29 on surface-2 in light** against a 4.5
  requirement, on the How / When / Where block that opens every component page.
  The ink, the mute, the rules and the texture now carry the site's value per
  theme: 5.40 and 4.70 respectively, and 17.74 for the body ink in dark. The two
  buttons on the docs home page measured 2.76 and 1.40 in dark for the same
  reason, and now take `--sdc-accent-text`.
- Do and Don't were `<h4>` under an `<h2>` on 21 pages, skipping a level. They
  are `<h3>`.

**47 pages, both themes, zero axe violations.** That was 83 contrast nodes and
42 heading-order nodes before.

### 02.02.00 · October 26, 2026

Added, nothing renamed.

- Two new components, [Field](/docs/components/field/) and
  [Slider](/docs/components/slider/), built for the MsMadeline type tester. Field
  is a labeled text input or textarea with an optional hint. Slider is the
  browser's own range input, tinted with the accent, with its value beside the
  label. Both live in the new `.sdc-field` block and use existing tokens only.
- **The rest of the control set**, which the 2026-10-22 inspection named as the
  system's largest coverage gap. Field gains `error`, `required`, `autocomplete`,
  `inputmode`, `disabled` and `placeholder`, so an invalid control now carries
  `aria-invalid` rather than only a color. Four more components:
  [Choice](/docs/components/choice/) for a checkbox or radio as a chip,
  [Fieldset](/docs/components/fieldset/) for a named group,
  [Select](/docs/components/select/) for the native picker, and
  [Form messages](/docs/components/form-messages/) for the error summary and the
  status live region, each in three tones so all six status tokens finally have
  a consumer: the tint is the ground, the ink sits on it, the solid draws the
  border. Proved out first on stevendesignservices.com, which built a
  contact form and a 52-question questionnaire on this system and had to invent
  every one of them locally.
- **Display 3**, as `.sdc-display-3`: the display face at `--sdc-text-heading`
  size, line height 1.1. Promoted from stevendesignservices.com, where it was
  `.sds-display-3` pending promotion. A class and not a token, because the size
  it wanted is already `--sdc-text-heading` to the character; what the scale
  lacked was a display-face treatment at that size, not a measurement. A
  Fieldset legend uses it.
- Two layout tokens for the control contract: `--sdc-control-h` (44px, which
  clears WCAG 2.2 target size with room) and `--sdc-control-border`. Two places
  had been writing `1px` by hand.
- No change to anything already on the site.
### 02.01.00 · October 22, 2026

Minor: tokens added, and one visual change that keeps every name.

- A status palette. Six semantic tokens, `--sdc-error`, `--sdc-warning` and
  `--sdc-success` with a tint each, over twelve new `--sdc-signal-*` primitives.
  Color primitives go from 16 to 28. Nothing uses them yet: there is no input,
  form or alert in the library, so for now they are a documented palette waiting
  for a control contract.
- Light is the default theme unconditionally. The `prefers-color-scheme` query
  and the first-visit check are gone, so a visitor whose machine is set to dark
  now gets the light palette until they ask for the other one. No name changed,
  which is why this is a minor and not a major.

### 02.00.00 · October 8, 2026

Breaking: every name the system owns gains the `sdc-` namespace.

- Tokens: `--accent` is now `--sdc-accent`, `--space-md` is `--sdc-space-md`,
  and so on for all 86. Figma keeps the plain names; the token build adds the
  prefix.
- Classes: `sdc-card` is `sdc-card`, `btn btn--primary` is `sdc-btn sdc-btn--primary`,
  `sdc-deck__track` is `sdc-deck__track`. Utilities take `sdc-u-`: `sdc-u-sr-only` is
  `sdc-u-sr-only`.
- Anything without the prefix is not the system's: a page's own layout class,
  an illustration's internal class, a state class such as `is-open`, or a
  variable private to one component.
- The version number added, in one file, shown here, in the Storybook and in a
  meta tag on every page.
- No visual change.

### 01.00.00 · October 7, 2026

The baseline: the system as it stood in production on October 7, 2026, at
commit `3b062e4`. It includes everything built before versions existed, among
it the Figma-generated primitive tokens, the overlay and logo shadow tokens,
Button padding on the spacing scale, and the documentation site.
