The current version is **SDC {sdc.version}**. The number lives in one file,
`src/styles/tokens/sdc-version.json`, and the site, the Storybook and these docs
all read it from there. The live site carries it too, in
`<meta name="sdc-version">`, so one request tells you which version is in
production.

## How the number works

Semantic versioning, the common practice: **major.minor.patch**, written with
two digits each, for example `02.00.00`.

| Part | Goes up when | Example |
| :-- | :-- | :-- |
| Major | Something that used the system before would break: a token, class or component name changes or goes away, or a component's markup contract changes. | Namespacing every token and class with `sdc-`. |
| Minor | Something is added without breaking what exists: a new token, component, pattern or variant, or a visual change that keeps every name. | Button padding moving onto the spacing scale. |
| Patch | A fix or a refactor that changes no name and no intended look: documentation, a bug fix that restores the intended rendering. | A docs page correcting a class name. |

The test is the consumer's code, not the visitor's eye. A rename is invisible
on the page and still a major version, because every selector and every
`var()` written against the old name stops working.

Each release gets a git tag, `sdc-` plus the number, on the commit that reached
production.

## Log

### 02.01.00 · October 23, 2026

Added, nothing renamed.

- Two new components, [Field](/docs/components/field/) and
  [Slider](/docs/components/slider/), built for the MsMadeline type tester. Field
  is a labeled text input or textarea with an optional hint. Slider is the
  browser's own range input, tinted with the accent, with its value beside the
  label. Both live in the new `.sdc-field` block and use existing tokens only.
- **The rest of the control set**, which the 2026-10-22 inspection named as the
  system's largest coverage gap. Field gains `error`, `required`, `autocomplete`,
  `inputmode`, `disabled` and `placeholder`, so an invalid control now carries
  `aria-invalid` rather than only a colour. Four more components:
  [Choice](/docs/components/choice/) for a checkbox or radio as a chip,
  [Fieldset](/docs/components/fieldset/) for a named group,
  [Select](/docs/components/select/) for the native picker, and
  [Form messages](/docs/components/form-messages/) for the error summary and the
  status live region. Proved out first on stevendesignservices.com, which built a
  contact form and a 52-question questionnaire on this system and had to invent
  every one of them locally.
- Two layout tokens for the control contract: `--sdc-control-h` (44px, which
  clears WCAG 2.2 target size with room) and `--sdc-control-border`. Two places
  had been writing `1px` by hand.
- Also first numbered here: the status palette that reached production on
  October 22, 2026: `--sdc-error`, `--sdc-warning` and `--sdc-success`, each with
  a `-tint`, over twelve `--sdc-signal-` primitives. See
  [Color](/docs/foundations/color/).
- No change to anything already on the site.

### 02.00.00 · October 8, 2026

Breaking: every name the system owns gains the `sdc-` namespace.

- Tokens: `--accent` is now `--sdc-accent`, `--space-md` is `--sdc-space-md`,
  and so on for all 86. Figma keeps the plain names; the token build adds the
  prefix.
- Classes: `sdc-card` is `sdc-card`, `btn btn--primary` is `sdc-btn sdc-btn--primary`,
  `sdc-deck__track` is `sdc-deck__track`. Utilities take `sdc-u-`: `sdc-u-sr-only` is
  `sdc-u-sr-only`.
- Anything without the prefix is not the system's: a page's own layout class,
  an illustration's internal class, a state class such as `is-open`, or a
  variable private to one component.
- The version number added, in one file, shown here, in the Storybook and in a
  meta tag on every page.
- No visual change.

### 01.00.00 · October 7, 2026

The baseline: the system as it stood in production on October 7, 2026, at
commit `3b062e4`. It includes everything built before versions existed, among
it the Figma-generated primitive tokens, the overlay and logo shadow tokens,
Button padding on the spacing scale, and the documentation site.
