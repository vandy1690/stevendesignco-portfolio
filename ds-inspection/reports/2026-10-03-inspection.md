## The short version

This system is in better shape than its age suggests, and the reason is unusual: the verification is further along than the thing being verified. Seven accessibility and layout checks run in CI on every change, each one proven by deliberately breaking it, and a gate blocks any change to a component that does not touch the documentation. Design and code agree on all 59 tokens, on names as well as values, which almost never happens by hand. A separate agent given only the documentation built a correct case study page without inventing a single prop.

The three things actually holding it back are all the same kind of problem, which is that a description somewhere has stopped being true. The file `CLAUDE.md` routes an agent to for this design system, `claude-context/design-system.md`, names the dark palette as the locked system, inverts the display and body fonts, and says the Figma library has not been located yet. `docs/DESIGN-SYSTEM.md` contradicts the shipped code in two places, both from changes made this week. `public/llms.txt` still describes Steve as looking for a Senior or Staff seat, which is below the floor and omits the Creative Director opening he just made, and `CONTRIBUTING.md` has a checklist item requiring that file to be true. The changelog stopped 30 commits ago, which means the single artifact a future reader would open first has no record of any of this work.

Fix the agent-facing design-system file first. It is one file, it takes twenty minutes, and every future session with an agent reads it before it reads anything else.

**Overall: 71/100** — a conversation starter, not a grade. Fix the reds, schedule the yellows, re-run on a cadence.

### Station 4 — Shared language: YELLOW (6/10)
- Swept: every prop on all 14 code components, all 68 CSS custom properties, all 59 Figma variable names, all 18 docs page titles; 13 concepts traced across design, code and docs
- Evidence level: design `live` · code `live` · docs `live`
- Findings:
  - [verified] The three-way trace fails more often than it passes. Only 5 of 13 traceable concepts carry the same name everywhere (Button, Pager, Eyebrow, Note, Section). The others speak three dialects at once: Figma "Meta pair" is code `CaseMeta` is docs "Meta row". Figma "Award row" is code `AwardList` is docs "Award list". Figma "Stat" is code `StatList`. Figma "Case block" is docs "Case study block". Figma "Quote" is docs "Recommendation quote".
  - [verified] Two systematic drifts cause most of that. First, the collection suffix: Figma says "row" or "pair", code says "List" or "Pair", docs says "list" or "row". Second, the prefix: code uses `Case*`, docs spells out "Case study *", Figma uses "Case *". Nothing is wrong in isolation; together they mean no name can be guessed from another asset.
  - [verified] `--text` is a colour and `--text-body` is a font size. Thirteen tokens in the `--text-*` namespace are type-scale sizes and two (`--text`, `--text-mute`) are foreground colours, with no delimiter to tell them apart. Figma escapes this because its collections (Colour, Type scale) do the disambiguating; CSS has no collections, so the name is all a reader gets. This is the sharpest naming defect in the system.
  - [verified] Three modifier conventions coexist with no written rule for which applies: t-shirt (`--space-sm`, `--radius-sm`, `--text-stat-lg`), numeric (`--surface-2`, `--paper-cloud-3`, `--text-display-1`), and semantic (`--rule-soft`, `--rule-strong`, `--text-mute`, `--accent-hover`, `--brand-regatta-deep`). `--text-display-1/-2` and `--text-stat/-stat-lg` express the same idea, a bigger version, two different ways.
  - [verified] Design and code disagree on the layout names and the code records the disagreement instead of resolving it: `--max: 1280px; /* layout/content-width */` and `--gutter: 24px; /* layout/content-padding */`. The Figma names are the better ones, and they live in CSS comments.
  - [verified] Prop vocabulary is otherwise consistent and deliberate. The collection prop is always `items` (AwardList, CaseMeta, StatList), the link prop is always `href`, the pass-through is always `class`, and `eyebrow` and `lede` mean the same thing in CaseBlock and CaseHero. No `size` vs `scale` vs `sz` problem anywhere.
  - [verified] Four prop names mislead about what they do. `hidden` on Pager is screen-reader-only text, but `hidden` is an HTML global attribute meaning do not render. `alt` is image alt text on CaseFigure and a darker background on CaseSection, same word, two meanings, two types, sibling files. `light` on CaseFigure looks like a boolean modifier and is actually a second image source, where `srcLight` would pair with `src`. `three` on StatList is a column count that can only ever say three.
  - [verified] No naming convention is written down anywhere: nothing in `docs/DESIGN-SYSTEM.md`, no CONTRIBUTING naming section, no lint rule or validator. Consistency is running on one person's memory, which is exactly why the three-way drift accumulated without anyone noticing.
- Not inspected: Figma layer-level names below the component level (sampled at Station 2, 32 of 34 meaningful)
- Deviations noted: none claimed as deliberate
- First move: pick one target vocabulary and rename across all three assets in one coordinated pass, starting with the `--text-*` collision. Nothing outside this repo consumes these names, so there are no downstream consumers to break and no codemod to generate. Then write the algorithm into `docs/DESIGN-SYSTEM.md` so the next pass has something to check against.

  - [verified] And it is all hand-maintained. There is no token pipeline: no token JSON, no Style Dictionary, no export or import step.   - [verified] Pager's variant property is `Direction=Previous|Next` in Figma and `dir='prev'|'next'` in code: same concept, different property name and different value spellings.

  - [verified] Three Figma components have no code component to trace to at all: Site header, Case card, Site footer, all implemented as page-level CSS (Station 1).

The pull request template requires the QA pass, a pixel comparison against live, documentation moving with the code, and both themes checked, and it carries three habits each traceable to a real regression.   - [verified] Guidance is not duplicated into drift. 12 of 18 docs pages reference their source file, and the 6 that do not are exactly the 6 CSS-only patterns with no component file to point at.
  - [verified] Code Connect would be the right mechanism for the Button mismatch and is not available on Steve's Figma plan, which returns a seat error rather than an empty mapping. Not a decision he declined to make.
